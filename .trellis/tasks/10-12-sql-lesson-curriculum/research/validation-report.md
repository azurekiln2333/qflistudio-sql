## Method

1. `build_content.py` renders `assets/content/sql_tutorials.json` and
   `assets/content/sql_examples.json` from the structured definitions under
   `tool/sql_curriculum/lessons/`, using the shared `ContentCatalog` schema.
2. `coverage.py` asserts counts (≥110 floor / 120 target), required fields,
   placeholder absence, `explain`/`code` uniqueness, and per-track minima.
3. `validate_content.py` executes each SQLite lesson `code` and each exercise
   answer in a **fresh throwaway database file** (never a real user database)
   via `sqlite3` 3.50.6, and compares against the **authored** expected result.
   Expectations are derived from the taught semantics and then asserted; the
   execution output is evidence, not the source of the expectation.

## Domain-result verification

- Each lesson declares `expected` (and each exercise its own `expected`) in
  SQLite CLI `|` row format, authored by hand from the concept being taught.
- The empty-result sentinel is `(no rows)`.
- Exercise answers run against the lesson `setup` in one session so TEMP tables
  and session state are visible.
